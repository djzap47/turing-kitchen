    SMALL RULES, BIG IDEAS

    What makes it a Turing machine?

    A model of computation introduced by Alan Turing in 1936.
    Not a modern processor, but a way to ask what any computer can compute.

    01

    A tape to remember

    Each cell stores one symbol. The tape is conceptually unbounded; our view follows the head and creates blank cells as needed. □ means blank, not zero.

    02

    A head to act

    The head reads one cell, writes a symbol, and moves left or right. Each click of Step applies exactly one transition from the rulebook.

    03

    A state to decide

    The current state and the symbol under the head select the next rule. The state graph shows the finite control; the visible rules drive every kitchen action.

    04

    A reason to stop

    A terminal state accepts or rejects. A missing rule halts as stuck. Pause only stops playback. Our 10,000-step playback cap is a practical limit, not a proof of non-halting.

    For the curious: the computer science underneath +

    M = (Q, Σ, Γ, δ, q₀, q_accept, q_reject)

    Q is the finite set of states. Σ is the input alphabet. Γ is the tape alphabet, including □ and completed-ingredient markers such as G and P. q₀ is the initial state. δ maps a nonterminal state and a read symbol to a new state, a written symbol, and a direction: δ(q, s) = (q′, s′, d).

    This simulator uses a deterministic, single-tape model with tape cells indexed by all integers and moves L or R. The pancake program transforms batter markers into ready-pancake markers. Tea and sandwich programs check ingredient order while recording preparation steps. Successful runs reach serve; invalid orders reach stop. Terminal states have no outgoing rules. The visible tape is a finite window; real computers have finite memory.

    A state graph edge can represent several rules. The table contains the full symbol-by-symbol definition. Rewind is a debugger feature backed by recorded history, not an extra operation of the mathematical machine.
